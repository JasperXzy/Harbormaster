## 待执行验证方法

1. 只读检查 sin-pro 的内核、nftables 支持、网卡、路由、NAT/转发、Docker/网桥、隧道和 flow offload；保存规则结构供恢复校验，输出不得带业务凭据。
2. 在专用 `inet harbormaster` 表增加纯计数规则，不 flush/覆盖现有表，不设置 drop/redirect/NAT。公网边界网卡入向在 DNAT 前观察远端源地址，出向在 SNAT 后观察目的地址；本机与转发均覆盖。同一方向在一个公网边界只计一次，不能 INPUT/FORWARD/POSTROUTING 叠加重复计数。
3. 排除 PRD IPv4 网段，以及 IPv6 回环、链路本地、ULA、多播等；仅按“目的不是私网”不足以区分私网网卡上去往公网的中转包，须同时限制边界网卡。实际隧道出口要统计云侧看到的外层字节。
4. CAP_NET_ADMIN 用于规则/计数；纯 TCP 连接不需 CAP_NET_RAW，ICMP/线路追踪到 M3 才按需增加能力。不启用任意 shell 命令的远程执行。
5. 每 10 秒记录双向累计字节、counter_epoch、单调时钟；每 5 分钟抓取 CMS 和已确认的 CDT 来源，覆盖至少 24 小时及整小时边界，等待官方补账稳定。按 sg-share 全体成员合并方向后比较。记录 GRO/GSO、offload、丢弃包、IPv6、NAT、隧道对口径的影响。
6. 分小时与全窗报告绝对字节差、相对差、缺测时段及时间对齐质量；官方量为 0 时单列绝对差，不除零。断网/计数器重置实验需要用户选定不影响服务的窗口，先不主动中断网络或重启机器。

## 结论与 PRD 修订建议

5% 准确性与 ≤20MB 常驻内存尚未验证，不能宣布达标。F12.3 应补充公网边界接口、NAT hook 与计数器 epoch，否则“排除私网地址”不能保证计费口径。掉线前峰值是保守估计方法，但不构成数学上的最坏上限；后续可增大流量，严格上界仍需配置带宽上限。该语义建议由用户确认，M0 不实现自动停机策略。
