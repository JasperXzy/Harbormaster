# 加密备份、下载与恢复

2026-11-12，F16.6 后端。已实现 CLI 导出、生产下载 API、流式文件认证及跨主密钥恢复命令。用户已确认恢复时取消旧任务和待发通知、清空租约；仅在合成数据和临时数据库中验证，没有操作真实数据目录。

## 使用范围

```sh
hm-server backup --data-dir /path/to/existing-data --output /path/to/new-backup.hmbak
```

原数据库的主密钥仍通过 `HM_MASTER_KEY` 或数据目录外的 `HM_MASTER_KEY_FILE` 提供。终端交互读取备份密码时不回显；脚本可从 stdin 提供。密码要求 12–1024 字节，不支持密码命令行参数，程序不保存密码。非交互输入去掉末尾一组 LF/CRLF，其余空白保留。

只接受已有生产数据库和新输出文件，不初始化缺失源库、不覆盖现有文件或符号链接。输出先写在目标目录的 0600 临时文件中，写完并同步内容后通过不覆盖的硬链接发布；不支持硬链接的文件系统会返回失败，不退回覆盖写。失败清理临时输出，不把半份备份当成成功文件。

备份内容是完整 SQLite 逻辑快照，包括历史、账号配置、任务、通知及不可逆 token 哈希。外部配置文件、二进制/agent 发布包与原主密钥不放入备份。原始任务/通知状态保存在档案中；恢复发布前按用户确认的策略取消未完成工作。

## 快照与凭据处理

1. 用独立的只读 SQLite 连接执行 `VACUUM main INTO ?`，生成包含已提交 WAL 数据的一致快照，不直接复制可能缺少 WAL 的主数据库文件。拷贝不长期占用服务器的单连接池，源库不改写业务数据。
2. 在 0700 私有临时目录中打开副本，验证原主密钥，逐一解密并重新加密 `credential` 的所有 owner 行（包括主密钥校验行）和 Telegram 渠道；仍使用原来的 owner AAD。新密钥来自备份密码，明文凭据只短暂存在内存，不写入文件。
3. 副本中清除登录会话，源库会话不变。再次 VACUUM 生成独立文件，去除旧密文及删除会话留下的空闲页，再加密整个文件。此步骤不会改变任务/通知执行状态。
4. 导出时 schema 必须与程序迁移集一致；恢复在初始化前只读核对来源为 production、迁移序列是已知连续前缀，拒绝空文件和未知未来 schema，再按现有机制迁移旧版本。将来新增可逆凭据存储位置时，必须同步纳入重加密路径。

依据：[SQLite VACUUM INTO](https://www.sqlite.org/lang_vacuum.html) 的一致快照和独立文件语义。暂存阶段需要副本空间，文件中的凭据始终是 AES-256-GCM 密文；临时目录在返回时清理。

## 格式 v1

| 部分 | 编码 |
|---|---|
| magic | 8 字节 ASCII `HMBK0001` |
| salt | 16 字节随机盐，每份备份独立生成 |
| 数据记录 | 4 字节大端密文长度，再接 `security.Box` 密文 |
| 结束记录 | 必须存在，明文为空的认证记录，长度为 29 字节 |

用 [Argon2id](https://pkg.go.dev/golang.org/x/crypto/argon2#IDKey) 从密码和 salt 派生 64 字节：time=3、memory=65536 KiB、threads=1。前 32 字节用于文件加密，后 32 字节用于副本凭据加密，原主密钥不被封装进档案。v1 参数固定，解析器不接受文件指定的任意 KDF 内存/时间参数。

文件每块明文最多 64 KiB，每块使用现有 `security.Box` 的 AES-256-GCM（版本字节、随机 12 字节 nonce、16 字节 tag）。AAD 包含整个 header、记录序号与数据/结束类型，以认证顺序和完整结尾。最多 2²⁰ 个数据块，即 64 GiB；读取长度上限在分配内存之前检查。密码派生需要约 64 MiB 工作内存，流式数据缓冲不随数据库大小增长；这不等同于已完成服务器常驻内存指标验收。

依据：[Go AEAD 接口](https://pkg.go.dev/crypto/cipher#AEAD)。格式测试覆盖换序、重复、截断、损坏长度、header/密文篡改与尾随字节，不把它描述为独立密码学审计。

`Unseal` 只产生隔离的待验证数据库及备份凭据密钥。调用方在认证错误时必须删除整个暂存结果；只有完整结束记录及 EOF 均验证通过后才可打开 SQLite。正式恢复命令会执行数据库及外键完整性检查、换成用户提供的外部主密钥、清除会话并处理旧工作，全部成功后才发布到新目录。

## 生产下载接口

`POST /api/v1/backups`，JSON body 为 `{"backup_password":"<用户输入>"}`，使用现有 HTTPS 管理会话、来源限制及 CSRF。密码不放在 URL、响应或日志中。长度按 UTF-8 字节计算，范围 12–1024。

每个进程同时只允许一个备份请求，与登录/初始化共享密码派生互斥限制；忙时返回 429。先在 0600 临时文件内生成并同步完整加密档案，再重新验证会话，返回 `application/octet-stream`、附件文件名及 Content-Length。准备失败返回 503 JSON，不返回半份附件；准备期间登出、重置密码或会话过期会阻止下载。传输断开可由 Content-Length 检测，临时文件随请求结束清理。

前端应保存二进制响应，不能将它当作 JSON。开发模式仍返回明确的 501，避免将合成开发库当作生产迁移备份。下载按钮与用户文案由 Claude 对接；本批未改 web/ 或 docs/design/。

## 恢复命令与已确认政策

```sh
HM_MASTER_KEY_FILE=/secure/target-master.key hm-server restore --input /path/to/backup.hmbak --data-dir /path/to/new-data
```

目标目录必须不存在，父目录必须已存在，主密钥文件须在目标目录外；输入备份密码仍使用隐藏终端或 stdin。可以使用与原机器不同的主密钥，不需要原主密钥。原外部配置和发布文件须另行部署，程序不会覆盖运行中数据库。

恢复先在目标父目录的 0700 暂存目录完成文件认证、数据库校验、凭据转换及工作状态处理。通过后创建目标目录，将完整独立数据库以不覆盖的链接发布。错误密码、损坏档案、无效数据库、未来 schema 或凭据认证失败都会丢弃暂存结果，不初始化目标目录。

用户已确认的取消策略落实为：

- queued/running 任务改为 failed，错误码 `backup_restored`，记录恢复时间；已完成任务历史保留。
- pending 通知改为 failed，错误码 `backup_restored`；标记结果不确定，因为旧备份无法证明这些消息后来是否已送达。已 sent/failed/not_sent 的历史不重发。
- 清空任务、通知和账号采集租约，下一次启动重新安排只读采集，不继续旧任务。
- 清空登录会话、一次性初始化令牌和 agent 注册码，避免重放旧的一次性授权；现有 agent/API Key 哈希按备份时状态保留。较备份更新的凭据轮换或撤销记录无法凭旧档案重建。

这些变化仅发生在待恢复副本，备份源库与源文件保持不变。恢复命令自身不启动 worker、不查询云接口、不发送消息。
