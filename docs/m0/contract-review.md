# M1 契约后端评审

2026-11-11。已阅读 `docs/api/openapi.yaml`（0.1.0-draft），修改理由如下。仍为草稿，未代表前端或用户确认冻结。没有修改 web/ 或 docs/design/。

## 已直接修改草稿

- 全局安全要求只保留 Cookie，在受保护写操作上单独声明 Cookie + CSRF；否则文档会要求 GET 和 EventSource 也携带 CSRF。登录/首次设置另外做来源校验。
- `official_bytes`、增量、估算、有效值允许 null；增加 `cutoff_unknown`。没有值不能显示 0，抓取时间不能冒充官方水位。理由见 V3。
- `counts_toward_cdt`、`settled_by_cdt` 允许 null；资格、拓扑、账号升级状态未确认时不能 false/true 二选一。理由见 V2/V4。
- `reset_day` 约束为 1（官方 CDT 周期）；若用户仍需自定义保护预算周期，另设字段，不改变云侧周期。此项为提交用户的 PRD 修订建议，不修改 PRD 原文。
- `DailyTraffic.data_timezone` 明确数据实际切分时区；缺数据的日期可为 null。不能将官方日桶强行标成任意业务时区。未知日值与已确认零流量须区别。
- 没有注入构建时间的二进制 `built_at=null`，不返回伪造日期。
- 共享带宽按主流量周期 3600 秒已由 V4 确认；安装时可提权，agent 服务仍需最小权限；代理响应不得回显 URL 中认证信息。
- 写明 M0 开发模式范围和未实现操作的 501 响应，避免前端把模拟联调当成真实能力。

前端需重新生成类型并处理新增可空值/状态，尤其不能在总额度池里将未知数据自动相加为零。后端没有改前端生成文件。

## B1–B21 答复

| 项 | 后端答复 |
|---|---|
| B1 | 官方 GB 换算基数仍待实际单位核实。接口一律整数字节；demo 中使用 1024³ 只是示例，不是官方验证结论。 |
| B2 | 接受响应体 csrf_token + X-CSRF-Token；GET 无需 CSRF，写请求校验会话绑定 token。 |
| B3 | 接受 hm_session、HttpOnly、SameSite=Lax；生产 HTTPS 加 Secure。M0 本机示例会话 1 小时，生产有效期留待配置方案确认。 |
| B4 | M0 示例使用单管理员无用户名；生产是否永久单管理员请用户确认，不扩展为多用户系统。 |
| B5 | fields 和 retry_after_seconds 可行，SDK 原始错误不直接作为 message 返回。 |
| B6 | 接受无续传保证、重连拉快照、15 秒 ping；10 秒周期内合并变化事件，慢连接断开重连，避免事件堆积。demo 提供 ping 与 quota.updated 示例。 |
| B7 | 当前约 10 台规模无需新增汇总接口，但前端必须拉完实例分页才能合计；账号 instance_count 可作为账号统计。 |
| B8 | 后端统一计算，但 protected 还要求可靠官方基准、已确认计费对象及可用计数，不能仅以 agent 在线判定。V3/V7 未通过前不宣称真实受保护。建议扩展描述，不在 M0 做保护引擎。 |
| B9 | 必须返回实际 data_timezone；只有足够细粒度源数据时才可重分桶为业务时区。 |
| B10 | 可信水位可用时可提供；否则 null，不制造“今日已知部分”。provisional 可用于未出账时段，不保证仅今天。 |
| B11 | 小时已确认；按全部成员方向分别求和，再取 max。 |
| B12 | 接受账号级官方/估算差值；资源级可来自 agent。CDT 2.0 账单存在资源粒度，但接口可用性/时效未验证，当前不承诺实时资源官方值。 |
| B13 | 接受前端提供模板，后端只传固定事件参数并渲染；本轮为占位文字，无实际发送。模板不得包含原始 SDK 错误、凭据或注册码。 |
| B14 | 接受固定枚举/参数，仅启用依赖已就绪的规则。 |
| B15 | 后端协议建议一次性码绑定实例、10 分钟过期、重发废弃旧未用码，现有长期 token 不因生成安装命令即失效；实际安装成功换发时再旋转。M1 实现。 |
| B16 | 接受 not_installed；撤销是管理动作，不当作偶发掉线告警，但对应实时保护立即不可用。 |
| B17 | 接受 202 + job_id。M0 不伪造发送成功或权限通过，相关写入口返回 501。 |
| B18 | PRD 未指定删除历史策略，待用户决定“删除账号同时清除历史”或“停用并保留历史”；本轮不实现删除。 |
| B19 | collection 可用于解释采集周期；官方水位缺失与抓取失败需单独状态，不能只靠一组固定过期时长判断。 |
| B20 | 当前规模接受小集合不分页；实例/通知继续游标。 |
| B21 | 接受 OpenAPI 3.0.3，不为 M0 增加 Go 生成器依赖。 |

## 尚待确认的字段限制

Instance 的单一 billing_subject_id 隐含单公网计费出口；遇多 EIP/多网卡不能任选一个当完整拓扑。当前真实实例出口待 V8，M1 前应决定是否改为列表。`BillingSubject.kind` 对未知拓扑还需明确未知状态；当前未确认对象不应伪装成某种已知计费类型。Telegram 代理认证如要支持用户名/密码，需单独 write-only 字段或明确保留旧认证的更新语义，不能将已加密密钥返回 URL。以上不通过临时实现替用户决定。

## 开发模式覆盖

`--dev` 提供现有契约的登录/登出、setup/status、session、system/info、settings、regions、accounts、instances（筛选/分页）、traffic/quotas、traffic/daily、traffic/billing-subjects、bandwidth-packages 及示例小时数据、notify/telegram、alert-rules、notifications、events。

除本机会话外，写入口返回 501；开发模式预初始化，无首次设置流程。实例、用量、通知是明确标注 demo 的合成快照，不来自真实云，SSE 不代表保护引擎已实现。真实 agent 上报的存储链路在 `/agent/v1/reports` 单独验证，不用面板 fixture 假装完成流量估算。
