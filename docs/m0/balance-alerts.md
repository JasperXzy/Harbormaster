# 可用余额低阈值告警

2026-11-12，对应 F9.5、F8.3、F8.8–F8.9。复用现有 BSS 余额查询，不增加云 API 调用。

## 配置与口径

规则 `balance_low` 默认启用、非紧急，初始 `params={"balance_thresholds":[]}`；没有配置的账号不产生余额告警。每个已有账号配置一个币种和金额，最多 100 项。PATCH 的 params 替换完整列表，空数组清除所有目标。

请求示例中的账号和金额仅为说明：

```json
{
  "params": {
    "balance_thresholds": [
      {"account_id": "acct_example", "currency": "CNY", "amount": "100.00"}
    ]
  }
}
```

来源选用费用接口已经提供的 `balance.data.available_amount`（可用余额），不是 `available_cash_amount`（现金余额）。币种必须与此次查询结果精确匹配；不按账号站点猜币种，不跨币种换算。阈值和源金额均使用十进制字符串与有理数比较，严格 `available_amount < amount` 才触发，相等即满足恢复条件。

金额接受带符号十进制，包括零，最多 12 位小数、80 字节且按 10¹² 缩放后不超过 256 bit；不接受 JSON 数字、科学计数、千分隔符或分数字符串。币种为 3 个大写字母。拒绝不存在或重复的账号、缺失/null 目标列表及其他规则的阈值字段；显式空数组有效。

## 事件与未知状态

- 只在 `SaveScan` 保存成功的余额观测时判断，使用当前账号修订号/任务租约校验后的数据；失败的余额读取、缺失/不合法数据、币种不匹配不会产生告警或恢复。
- 独立的一秒告警扫描只维持已有状态，不拿旧缓存金额重新判断。修改金额后在下一次成功余额查询时使用新条件。
- 持续不足只记录一个 incident；成功查询确认金额达到阈值后记录 recovery，之后再次不足才记录新 incident。账单查询失败不阻止一份有效余额触发告警。
- 移除目标或改变币种时，旧条件静默结束并取消对应待发消息，不制造“余额恢复”结论。修改其他账号不会重置本账号的 incident。规则关闭或账号停用沿用现有取消机制。
- 告警状态、通知及余额缓存在同一个事务内提交；通知写入失败会回滚本次余额记录，重试不会留下半份状态。

余额刷新当前跟随资源扫描周期（默认 300 秒），不是秒级计费或流量额度估算。通知文案为占位文字，Telegram 实际发送仍未接通；没有配置渠道时记录为 `not_sent`。

## 前端对接

先在 OpenAPI 增加了规则枚举、`balance_thresholds` 字段和校验说明，再实现后端。开发模式也返回该规则及空目标列表。前端需配置每个账号的币种/金额，并按费用接口的可用余额说明展示；本批不改 web/ 或 docs/design/。

## 验证

自动测试覆盖：未配置不告警；可用余额和现金余额区分；严格小于/等于边界、12 位小数；失败/不同币种/无效源不误恢复；重复检测去重、恢复与再次发生；阈值修改等待新数据；移除/改币种取消旧消息；账号停用；配置不存在/重复账号、错误格式或其他规则字段被拒绝；事务回滚及账单失败时余额仍独立有效。
