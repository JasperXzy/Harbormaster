# 流量页的多账号合计

2026-11-18。用户要求在流量页账号选择器增加合计选项，沿用前后端分离和分阶段验证、提交、部署方式。真实电源与释放继续关闭。

契约先记录变更：`GET /traffic/quotas?account_id=all`、`GET /traffic/daily?account_id=all` 汇总启用账号；省略参数及单账号查询保留原语义。停用账号可单独查看历史，不参加合计。没有启用账号时返回空结果，不返回凭空的零用量。

合计在 Go 中完成，只读取现有缓存和官方累计读取记录，不新增云查询、任务或数据库迁移。完整官方值、实时估算和月底预测分别要求全部账号有相应数据；缺少或过期时保留 null，并返回覆盖账号数和已知小计。已知零与未知继续区分，整数溢出不绕回。合计估算始终不具备真实执行资格，原始单账号数据和严格对齐字段不受影响。

每日按业务时区日期连接，缺账号或范围保留缺口；官方／采集混合来源明确标为 mixed。只有全部账号都覆盖完整的已结束日期才是完整合计日。官方曲线只在每个账号都有同一读取日期记录时合计，不向缺失日期填零或沿用别日数值。

月底预测相加各账号独立计算的月末值和共同未来日期的预测点。各账号的样本不强行改成同一批日期，返回样本天数范围；基准合计明确为不同时间的独立值，不冒充统一官方 cutoff。免费额度不能跨账号使用，因此不生成“额度池预计超额日期”；单账号预测超额数量单独提示，切换账号可查看详情。所有结果仅供展示。

前端保留原来的默认账号，新增“全部账号（合计）”。本月用量、每日图表／表格、累计预测、公网出口及带宽包随之切换；原始官方读取记录仍按账号分别展示。开发模式和前端示例响应也支持相同查询。
