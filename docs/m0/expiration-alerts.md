# 到期提醒与恢复

2026-11-12，PRD F9.3 / F8.3 / F8.8。已接入 instance_expiring 规则和通知记录；默认 before_days=7，来源为新采集的包年包月实例到期时间。Telegram 发送尚未接入，不能将本阶段视为已收到消息的验收。

## 判定

每次资源扫描成功返回某个 ECS / SWAS 实例后，在 SaveScan 的同一事务内检查到期时间。`expires_at <= 当前时间 + before_days × 24 小时` 时建立提醒，已过期的实例也满足该条件。阈值可通过现有告警规则 API 调整为 0–365 天，0 表示到期后才提醒；规则默认开启、非紧急、warning 级别。

只使用本轮真实返回的资源行，不因时间推进而把旧缓存变成新的到期证据；云端读取失败、缺少到期日期、日期无法解析或计费方式未知时，不建立新提醒，也不伪造恢复。首次进入窗口通常在下一次成功资源扫描时发现，默认扫描周期为 300 秒，不能承诺脱离采集周期的即时提醒。

停止运行的包年包月实例仍然有到期风险。自动续费已开启也不取消提醒，因为策略开启不证明之后支付成功；通知占位内容附带该次读取的续费状态。按量或抢占式实例不适用包年包月到期提醒。

## 去重、恢复和取消

迁移 011 为 alert_state 增加 basis，保存规范化 UTC 到期时间。同一活动事件、相同到期日期的重复采集不会重复入队，状态和通知事务持久化后可跨重启去重。

- 新日期已离开提醒窗口，或已确认改为不适用到期提醒的计费类型：取消尚未发送的旧提醒并记录 recovery。
- 日期变化但仍在提醒窗口：更新为基于新日期的提醒，取消未发送的旧提醒，不谎报“已恢复”。
- 到期日期缺失或来源暂时未知：保留已有活动状态，不产生虚假恢复。
- 规则关闭、账号停用或资源已确认不再纳管：静默关闭相应事件并取消待发记录，历史保留。停止实例本身不会关闭到期事件。

source-health 评估器只负责维护当前纳管目标是否仍适用，不用缓存日期自行创建到期事件。过期事件与资源快照必须共同提交；通知写入失败时整个扫描事务回滚，避免出现“状态已记为提醒、但通知丢失”。
