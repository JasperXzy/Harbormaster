# 流量页、每日统计与预测

2026-11-18。用户重新授权由 Codex 接入前端，在现有视觉和独立 web/ 工程上补功能；保持 Go API 与静态前端独立构建和发布，不开启真实电源或释放。

## 口径确认

用户确认：有可验证的官方日数据时优先使用；否则按 agent 与计费对象规则生成“采集估算”，保留缺口。预测使用最近 7 个完整日；不足 7 日时允许已有完整日样本，并显示天数，今天未结束的时段不加入日均。

## 第一阶段：实时估算展示

先通过原有前端的 `npm test`（3 个通过）与 `npm run build`，将既有未提交前端保存为独立提交 `4b4d5cf`，不丢弃或混入设计目录的改动。

修正 OpenAPI 的 nullable object 声明和一个 flow-map 文案的逗号引用，使用 `--default-non-nullable false` 生成类型，避免把“某些规则的默认参数”误解为所有规则都必填。补齐新增规则标签和 mock 必填字段。

前端集中选择展示值：ready 的 estimation 可以显示未核实估算，旧的严格对齐字段仍保持原样；缺口／不可用不拿已知小计充当完整用量；过期值保留上次结果并标识过期，不用于剩余额度合计。总览、流量表、手机额度卡、顶部时间和实例采集状态使用同一口径。额度更新间隔调整为 10 秒，沿用 SSE。删除“官方约晚一小时”的确定性说明，改为本地窗口假设。

`npm test`：5 个通过，覆盖未核实值可展示、严格字段不被修改、已知零／未知区别、部分范围不汇成完整剩余、过期值和累计曲线缺口。`npm run build`：TypeScript 与 Vite 通过。浏览器验证“截止未知”场景，海外有数字和“未核实估算”标记，国内显示覆盖原因及已采集部分，没有标成真实保护；正常场景保留既有图表。

## 第二阶段：每日计量与月底预测

先改 OpenAPI 并在顶部记录变更。新增每日范围元数据和后端预测结果，保留原有 nullable 日字节字段以便独立升级前端。每日缓存按账号、凭据版本、账号修订、业务时区和日期隔离；HTTP 读取缓存，不遍历原始 agent 月历史。

迁移 049 保存完整发现时的计费关系版本。既有稳定发现只能作为“观测到的关系”导入，不能变成阿里云证明的挂载时间；旧指纹未包含公网地址，空共享带宽的已知零只能从包含地址列表的观测起算。发现失败、变更或间隔超过 15 分钟留下覆盖缺口。无成员但仍有关联公网地址的对象保持未知。

采集日统计复用按对象的计量组件：按出方向计费的对象只算 TX；共享带宽先汇总所有成员的 RX/TX，再按 UTC 小时取较大值。缺口、未知成员、重复归属均不成为完整日。原始累计区间跨小时／午夜时使用有标记的上界分配，不假设均匀流量；因此相邻日期的估算可能重复分配边界样本，不能视为官方账单。每日统计只使用实际累计差值，不加入离线最坏值预测。

只有来源、凭据、已验证月份和精确业务日边界均一致的两次官方累计值，才能形成官方每日值。当前 CDT 适配器没有这些边界，仍走明确标注的采集估算；抓取时间的差值绝不冒充每日用量。官方累计曲线保留每个读取日期最后一份成功记录，横轴表示读取日期。

接收样本的事务通过 SQLite trigger 同时登记重算事件。后台每轮最多消化 1000 个事件（按受影响日期去重），每账号最多计算 6 个日期，各日期独立事务，每 30 秒运行。迟到的同 epoch 累计区间会替换受影响日的缓存；不重复累加恢复数据。日期缓存持久化，已完成日不因每次页面读取反复扫描原始样本。

预测的“近 7 天”明确为业务时区内最近 7 个已结束的日历日，从中选择覆盖完整、当前没有待处理修订的日期；不向更久的日期补足样本。至少 1 个完整日才显示预测，并返回样本天数和日期。采用整数向上取整日均，从当前实时估算时间延伸到月底；只有官方累计可用时，使用其明确的 cutoff 或已标明假设的延迟窗口。按各业务日剩余比例外推，不把今天完整一天再加一次，支持 DST，溢出拒绝计算。已超额与未来预计超额分开返回。所有结果仅供展示，不改变真实保护资格或真实电源／释放开关。

验证包括：已采集部分不成为全天总量；午夜后的第一个累计样本可修复前一天并保留上界标记；迟到事件重算后反复读取不重复计数；官方日数据必须有精确、已验证的两端；显式空带宽包与未知地址列表区分；今天／缺口／待重算日期不参加日均；少于 7 日可预测并显示样本数；零日均和整数溢出。

## 第三阶段：前端日统计与预测接入

保留独立 `web/` 工程和现有样式。每日图表分别处理国内／海外的可用数值，一个范围未知时仍显示另一个范围；浅色虚线边表示已采集部分，表格列出来源、完整日状态和首末观测时间。官方日数据、完整日采集估算、部分覆盖、待汇总和未知分别展示。日缓存每 30 秒更新。

累计视图可以在整月采集前缀缺失时单独显示官方累计读取点和当前估算；不从未知日期之后拼接“从零起”的累计。预测完全使用 Go 返回的预测点，基准与当日日终分为两个槽位，避免前端另算一套月末值。明确标注样本数量、日期、未核实状态和无完整样本的等待原因。手机额度卡也显示样本数和未核实预测。
