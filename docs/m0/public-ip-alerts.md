# 公网 IPv4 变化告警记录

2026-11-12，对应 F8.3、F8.9 和第 10 节“实例公网 IP 变化：每次”。使用上一阶段的[实例变化事件](instance-events.md)，不会发起额外云查询。

新增规则 `instance_public_ip_changed`，默认启用、非紧急、`params={}`；API 与开发模式均已提供。既有阈值参数对这条规则不适用，会返回验证错误。文案继续使用占位文字，由前端定稿。

## 行为

- 仅新生成的 `public_ipv4_changed` 事件产生告警记录，覆盖 ECS 和轻量。事件、通知、比较基准、资源快照同一个事务提交。
- 首次发现、升级时建立基准、地址重排或重复、数据源失败、部分 IPv4 拓扑、仅 IPv6 分配地址变化均不触发公网 IP 告警。
- 已确认地址集合变为空、从空变为有地址、再次返回原地址均是一次新变化，每次各记录一条。它不是持续故障，不写活动 incident，也不制造 recovery 消息。
- 以持久化实例事件 ID 作为通知事件键，重复扫描不会重复生成，失败事务重试不会只留下通知或只留下事件。
- 规则关闭后仍记录资源变化历史，停止生成通知并取消尚未发送的同规则通知。重新启用不补发关闭期间的历史；之后的新变化正常记录。账号停用同样保留历史并取消待发通知。

未配置 Telegram 渠道时为 `not_sent`；有渠道时沿用 outbox 的 `pending` 状态。实际发送 worker 尚未接通，pending 不代表已经发送。每条占位消息引用 `instance_event_id`，完整前后地址集合可在 `/instance-events` 中查询，不将整个云响应或凭据复制进通知。现有 `/notifications` 查询与 SSE 能看到新增记录及取消结果。

## 验证

自动测试模拟完整资源扫描，覆盖：ECS/轻量变更、首次发现不告警、集合去重、部分来源不告警、IPv6 不误用为公网资格、每次变化独立记录、重复扫描去重、无虚假恢复、规则开关不回放旧事件、账号停用取消待发，以及通知写入失败时回滚事件与快照、重试只产生一条记录。

## 前端与后续

契约已先增加规则枚举和说明。前端需要适配新规则名称和占位消息文案；本批不修改 web/ 或 docs/design/。无需新增产品决策。IPv6 当前只有分配地址证据，所以仍仅记录其变化历史，不据此触发“公网 IP”通知；若以后接入 IPv6 公网能力来源，再扩展本规则。

真实送达、静默时段、Telegram 响应丢失后的重试策略仍按总体待办推进，本批只完成告警记录链路。
